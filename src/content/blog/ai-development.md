В 2026 году писать очередной личный сайт с нуля, вручную верстать каждую страницу и городить админку ради десятка статей — сомнительное удовольствие.

Особенно когда под рукой есть ChatGPT, Codex и бесплатный GitHub Pages.

Я решил собрать себе личный блог разработчика. Без WordPress, базы данных, платного хостинга и прочего зоопарка. А заодно подумал: почему бы не прикрутить AI-агента, который будет сам готовить статьи, а мне останется только одобрять публикации?

Разбираемся, что для этого нужно.

## ChatGPT + Codex: один думает, второй пишет код

Начнём с самого полезного.

**ChatGPT** — для обсуждения архитектуры, дизайна, структуры сайта и технических решений.

**Codex** — AI-агент, который непосредственно работает с проектом: создаёт файлы, меняет код, запускает команды и исправляет ошибки.

И приятный момент: Codex уже входит в подписку ChatGPT Plus в пределах установленных лимитов.

Не нужно отдельно покупать API-токены, чтобы пользоваться им через поддерживаемые интерфейсы с авторизацией ChatGPT.

Работать можно через расширение VS Code, терминал или отдельное приложение.

Мой сценарий простой:

1. В ChatGPT обсуждаю дизайн и структуру блога.
2. Открываю проект в VS Code.
3. Передаю Codex конкретную задачу.
4. Проверяю результат в браузере.
5. Если что-то криво — возвращаю агенту на исправление.

Всё. Никакой магии. Просто меньше рутины.

## Astro: зачем мне Next.js ради пяти страниц?

Я React-разработчик, но тащить Next.js в небольшой статический блог не захотелось.

Выбрал [Astro](https://astro.build/).

Почему?

- Генерирует готовые HTML-страницы.
- Не требует постоянно работающего Node.js-сервера.
- Поддерживает Markdown для статей.
- Позволяет использовать React, если понадобится.
- Хорошо подходит для SEO благодаря статической генерации.

Запускается буквально несколькими командами:

```bash
npm create astro@latest my-blog
cd my-blog
npm run dev
```

Дальше отдаём Codex задачу сверстать сайт.

Для моего блога достаточно четырёх разделов: «Обо мне», «Работы», «Статьи», «Контакты».

Тёмный фон, обычная типографика, минимум декоративных элементов.

**Мне нужен сайт, а не выставка CSS-анимаций.**

## GitHub Pages: хостинг за ноль рублей

Самое приятное — за размещение статического сайта можно вообще не платить.

[GitHub Pages](https://pages.github.com/) позволяет бесплатно публиковать сайты из публичных репозиториев.

Как это работает:

1. Создаём репозиторий GitHub.
2. Загружаем Astro-проект.
3. Настраиваем GitHub Actions.
4. Подключаем собственный домен.
5. Получаем работающий сайт с HTTPS.

Я использую домен `webreznov.ru`, зарегистрированный на REG.RU.

Для подключения достаточно настроить DNS-записи и указать домен в GitHub Pages.

А дальше публикация статьи выглядит так:

```bash
git add .
git commit -m "Add new article"
git push
```

GitHub Actions собирает Astro и обновляет сайт.

**Никакого VPS, Nginx, Docker и возни с сертификатами для самого блога.**

## OpenClaw: а что, если блог будет писать себя сам?

Вот тут начинается самое интересное.

[OpenClaw](https://openclaw.ai/) — AI-агент, которого можно развернуть на собственном сервере и подключить к Telegram.

Моя идея — поставить его на небольшой VPS, предоставить ограниченный доступ к репозиторию блога и настроить ежедневную подготовку статей.

Допустим, каждое утро агент:

1. Выбирает тему из заранее подготовленного списка.
2. Собирает информацию и проверяет источники.
3. Пишет статью на 500–1000 слов.
4. Создаёт Markdown-файл с SEO-заголовком и описанием.
5. Присылает мне черновик в Telegram.

Я читаю, при необходимости прошу исправить и подтверждаю публикацию.

После подтверждения агент создаёт Pull Request, а я проверяю и объединяю изменения. GitHub Actions публикует новую статью.

**Получается практически автоматический технический блог.**

Но есть нюанс: AI прекрасно умеет писать убедительную чушь. Поэтому полностью бесконтрольную публикацию я бы не включал.

Особенно если речь про технические инструкции, версии библиотек и команды, которые читатели будут запускать у себя.

И ещё: агенту не нужны права на все мои репозитории. Отдельный токен с минимальными разрешениями, изолированная рабочая среда и подтверждение публикации — обязательный минимум.

## Сколько стоит такая AI-связка?

| Инструмент | Стоимость |
|---|---|
| ChatGPT Plus + Codex | Подписка, лимиты включены |
| Astro | Бесплатно |
| GitHub Pages | Бесплатно |
| OpenClaw | Бесплатное ПО |
| VPS для OpenClaw | Зависит от тарифа |
| AI-модель для OpenClaw | Зависит от модели и способа доступа |
| Домен | Оплата продления |

Важный момент: подписка ChatGPT Plus не означает, что любые API-запросы из OpenClaw будут бесплатными. Авторизацию и стоимость используемой модели нужно проверять отдельно.

И не стоит рассчитывать, что OpenClaw гарантированно нормально заработает на самом дешёвом VPS. Всё зависит от доступной памяти, окружения и выполняемых задач.

## Итог: разработчик нужен, но писать всё руками уже необязательно

Получается довольно забавная цепочка:

**ChatGPT → Codex → Astro → GitHub Pages**

Так создаём и размещаем сайт.

А дальше:

**OpenClaw → статья → Telegram → моё одобрение → GitHub → деплой**

В итоге у меня есть личный блог, который не требует платного хостинга и отдельной админки. А в перспективе — агент, способный самостоятельно готовить материалы.

При этом не стоит путать автоматическую генерацию контента с качественным блогом.

Если публиковать каждый день очередной пересказ документации, толку будет немного. Гораздо интереснее добавлять собственный опыт, реальные ошибки, результаты экспериментов и конкретные решения.

**Пусть ИИ делает рутину. А мне оставит то, ради чего вообще интересно заниматься разработкой.**
