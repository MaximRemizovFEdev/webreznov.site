# Docker для frontend-разработчика: хватит запускать всё через npm start

Долгое время я прекрасно обходился без Docker. React, Node.js, `npm install`, `npm run dev` — что ещё нужно фронтендеру для счастья?

А потом появляются VPS, несколько приложений, разные версии Node.js и классическое: «У меня локально всё работает».

Вот тут Docker начинает выглядеть не очередной модной технологией, а вполне полезным инструментом.

## Docker — это вообще что?

Если совсем просто, **Docker позволяет упаковать приложение вместе с необходимым окружением в контейнер**.

Раньше я экспериментировал с виртуальными машинами. Docker решает похожую задачу изоляции, но контейнеры используют ядро операционной системы хоста, поэтому обычно легче полноценных виртуалок.

Вместо ручной установки Node.js и настройки окружения на каждом сервере описываем всё в `Dockerfile`.

## Dockerfile для React-приложения

Допустим, у нас обычный React + Vite.

```dockerfile
FROM node:22-alpine AS build
WORKDIR /app

COPY package*.json ./
RUN npm ci

COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html

EXPOSE 80
```

Что происходит?

1. Docker берёт образ Node.js.
2. Устанавливает зависимости.
3. Собирает frontend.
4. Копирует готовую сборку в Nginx.
5. Запускает статический сайт без Node.js в финальном контейнере.

Собираем и запускаем:

```bash
docker build -t my-frontend .
docker run -d -p 8080:80 my-frontend
```

Открываем `localhost:8080` — приложение работает.

## А зачем Docker Compose?

Когда появляется backend, база данных и frontend, запускать каждый контейнер вручную становится неудобно.

**Docker Compose** позволяет описать несколько сервисов в одном YAML-файле и запустить их одной командой:

```bash
docker compose up -d
```

Для моих проектов это особенно удобно: frontend и backend живут в отдельных контейнерах, а обновление приложения не требует ручной переустановки зависимостей на VPS.

## Нужно ли фронтендеру учить Docker?

Если ты исключительно верстаешь компоненты — необязательно.

Но если хочешь самостоятельно запускать проекты, работать с VPS, настраивать деплой или разрабатывать fullstack-приложения — однозначно стоит.

Не нужно сразу становиться DevOps-инженером. Для начала достаточно разобраться с образами, контейнерами, Dockerfile, Compose, портами и volumes.

**Docker не сделает тебя лучшим React-разработчиком. Зато избавит от кучи возни, когда приложение нужно запустить где-то кроме собственного ноутбука.**
