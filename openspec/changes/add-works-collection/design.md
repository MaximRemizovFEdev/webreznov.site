## Context

Текущая `/works` содержит один `<li>` в `src/pages/works.astro`. Статьи уже используют Astro Content Collections, общий источник опубликованных записей и динамический маршрут. Новая возможность должна повторить этот проверенный контур, не меняя архитектуру статей.

## Goals / Non-Goals

**Goals:**
- Хранить каждый проект отдельно в Markdown.
- Использовать единый валидируемый формат метаданных.
- Генерировать список и подробные статические страницы из опубликованных проектов.

**Non-Goals:**
- Админ-панель, CMS, изображения через отдельный media pipeline и фильтрация по тегам.
- RSS для проектов.
- Изменение URL или формата статей.

## Decisions

### Отдельная коллекция `works`

Зарегистрировать `works` рядом с `blog` в `src/content.config.ts`, используя локальный Markdown loader и схему полей. Отдельная коллекция сохраняет независимые правила публикации и не смешивает проекты со статьями.

### Общий helper опубликованных проектов

Добавить `src/lib/works.ts` с фильтрацией `draft`, сортировкой по `order` и стабильным вторичным ключом `id`. `/works` и `works/[id].astro` используют один источник, чтобы черновик не появился только в одном из каналов.

### Плоские имена файлов и статические маршруты

Имя файла без `.md` становится идентификатором URL. Страница `/works/[id].astro` получает опубликованные записи через `getStaticPaths` и рендерит Markdown через Content Collections. Переименование файла считается изменением URL.

### Минимальная схема метаданных

`title`, `description` обязательны; `role`, `url`, `featured` и `order` необязательны. `draft` по умолчанию false. Поле `url` не выводится, если его нет; это позволяет безопасно описывать незавершённые или внутренние проекты.

### Перенос текущего проекта

Создать `src/content/works/ai-da-skazka.md` с текущим подтверждённым названием и описанием. Не добавлять URL, стек или дополнительные факты без данных от владельца.

## Risks / Trade-offs

- [Переименование файла меняет URL] → Использовать стабильные kebab-case имена и считать переименование изменением публичного адреса.
- [Markdown проекта может быть пустым] → Список всё равно использует title/description, подробная страница остаётся валидной.
- [Порядок featured не определён] → В первой версии сортировать только по `order`; `featured` хранить для будущей визуальной группировки.

## Migration Plan

1. Расширить content config и добавить helper коллекции.
2. Перевести `/works` на коллекцию и создать динамический маршрут.
3. Перенести «Ай да сказка» в Markdown и удалить зашитый элемент списка.
4. При необходимости добавить новые проекты отдельными файлами без изменения маршрутов.
